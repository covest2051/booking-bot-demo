# Telegram-бот онлайн-записи для салона или мастера

Клиент записывается к мастеру за несколько нажатий прямо в Telegram, получает напоминания и сам отменяет запись.
Администратор получает уведомления о каждой записи и отмене и видит расписание на день и на неделю.

## Что умеет

**Клиент**
- запись: услуга → мастер или «любой свободный» → дата → время → подтверждение;
- показываются только реально свободные дата и время с учётом длительности услуги, графика и выходных мастера;
- «Мои записи» и отмена (не позже чем за N часов до визита, по умолчанию 3);
- напоминания за сутки и за 2 часа;
- номер телефона — одной кнопкой «Поделиться номером», вводить вручную не нужно.

**Администратор**
- уведомление о каждой новой записи и отмене;
- `/today`, `/tomorrow`, `/week` — расписание по мастерам с телефонами клиентов;
- отмена любой записи в одно нажатие, клиент получает уведомление;
- `/off` — выходной мастеру на выбранный день, `/offs` — список и снятие выходных.

**Надёжность**
- двойная запись на одно время невозможна даже при одновременных нажатиях: это гарантирует база данных, а не проверка в коде;
- напоминание приходит ровно один раз, в том числе после перезапуска бота;
- данные хранятся в PostgreSQL, бот переживает перезапуск сервера.

## Настройка под салон

Всё, что отличает один салон от другого, лежит в [`salon.yml`](salon.yml): название, адрес, телефон, услуги с длительностью
и ценой, мастера с их услугами и графиком по дням недели, правила записи (шаг сетки, за сколько можно отменить и т. д.).
После правки бот перезапускается.

## Запуск

Нужен сервер или компьютер с Docker.

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Скопируйте `.env.example` в `.env` и заполните: токен, Telegram id администраторов, пароль базы.
3. `docker compose up -d --build`
4. Администратор один раз нажимает `/start` в боте — иначе Telegram не даст боту ему писать.

Логи: `docker compose logs -f bot`.

## Для разработчиков

Java 21, Spring Boot 3.5, Spring Data JPA, PostgreSQL, Liquibase, [TelegramBots](https://github.com/rubenlagus/TelegramBots) (long polling).

- Пересечение записей запрещено ограничением `EXCLUDE USING gist (master_code WITH =, tstzrange(starts_at, ends_at) WITH &&) WHERE (status = 'ACTIVE')`
  ([001-init.sql](src/main/resources/db/changelog/001-init.sql)). Уникальный индекс по началу не подходит: записи 10:00 на 60 минут
  и 10:30 на 30 минут начинаются в разное время, но пересекаются.
- «Любой мастер»: каждая попытка вставки идёт в отдельной транзакции ([BookingService](src/main/java/dev/bookingbot/booking/BookingService.java)),
  потому что после нарушения ограничения транзакция в PostgreSQL уже не годится для повторной попытки.
- Напоминания ([ReminderJob](src/main/java/dev/bookingbot/booking/ReminderJob.java)) сначала «захватываются» условным `UPDATE … WHERE reminded_at IS NULL`,
  потом отправляются; при ошибке Telegram захват снимается и отправка повторяется.
- Диалог без хранимого состояния: выбранные услуга, мастер, дата и время лежат в `callback_data` кнопок (лимит Telegram — 64 байта, поэтому в конфиге короткие коды).
- Long polling: не нужны домен и HTTPS, но запускать можно только один экземпляр бота.

Тесты (нужен запущенный Docker для Testcontainers):

```bash
mvn test
```

Запуск без Docker-образа бота (база — любая PostgreSQL):

```bash
DB_URL=jdbc:postgresql://localhost:5432/booking BOT_TOKEN=... ADMIN_IDS=... mvn spring-boot:run
```
